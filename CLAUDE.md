# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A pure Bash installer that provisions a macOS web development AMP stack (Apache, MySQL/MariaDB, multiple PHP versions, Dnsmasq) via Homebrew, plus a `sphp` PHP-version switcher. There is no build step, no package manager manifest, and no test suite — it is shell scripts that shell out to `brew`, `sed`, `perl`, and `sudo`.

## Commands

```bash
./macos-web-development.sh                 # DRY RUN by default — prints what it WOULD do, changes nothing
./macos-web-development.sh --no-dry-run    # actually install
./macos-web-development.sh --help          # full option list (generated by lib/print_help.sh)
./macos-web-development.sh --uninstall --no-dry-run
./self-install                             # copy repo to /usr/local/macos-web-development + symlink into /usr/local/bin
sphp 8.4                                   # switch active PHP version (installed to /usr/local/bin/sphp)
```

**Dry run is the single most important convention.** Every destructive action in `lib/` is guarded by `if ! $DRY_RUN; then ...`. When adding any command that writes files, installs packages, or calls `sudo`, you MUST wrap it in this guard, and ideally print what would happen in the `else`/dry-run branch (see `do_apache.sh` for the `sed -n ...p` "preview" pattern).

There is no automated test harness. To validate changes, run the script in dry-run mode and read the output.

## Architecture

`macos-web-development.sh` is a thin orchestrator. It resolves its own directory (handling the symlink case for self-installed copies), then `source`s **every** file in `lib/*.sh` alphabetically, then calls the `do_*`/`set_*` functions in a fixed order. All real logic lives in `lib/`.

Execution order in the main script (the mental model for the whole tool):
1. `init_colors.sh`, `init_options.sh` — sourced; run at source-time, not as functions.
2. `print_help` (exit early if `--help`).
3. `do_dry_run_message`, `do_sudo`.
4. `do_self_update` (exit early if `--self-update`).
5. `set_variables`, `set_homebrew_path` — populate globals consumed by everything downstream.
6. `do_uninstall` (exit early if `--uninstall`).
7. Install phase: `do_xcode`, `do_homebrew`, `do_openldap`, `do_libiconv`, `do_mysql`, `do_dnsmasq`, `do_apache` + `do_hosts`, `do_php` + `do_php_enable`, `do_finish`.

### Globals contract (important)

The codebase relies entirely on shared global variables — there are no return values or arguments passed between functions. The two key initializers:

- **`init_options.sh`** parses CLI flags into booleans (`INSTALL_*`, `ONLY_*`, `PHP_x_y`, `DRY_RUN`, `UNINSTALL`, etc.), then applies **preset/`--only-*` logic** that flips `INSTALL_*` flags off. When adding a flag, update the `while`/`case` parser AND `lib/print_help.sh` AND, if it gates a component, the preset block.
- **`set_variables.sh`** builds the PHP version list. `ALL_PHP_VERSIONS` is the canonical version array; `--only-php-x-y` flags take precedence, otherwise all non-`--no-php-x-y` versions are used. `LATEST_PHP_VERSION` (last element) drives `do_php_enable`.

`set_homebrew_path.sh` resolves `HOMEBREW_PATH` via `brew --prefix` (differs Intel `/usr/local` vs Apple Silicon `/opt/homebrew`) and derives all Apache/MySQL paths from it. Never hardcode `/usr/local` or `/opt/homebrew` — read from these globals.

### Adding or bumping a PHP version

A PHP version is referenced in several parallel arrays/flags that must stay in sync:
- `lib/init_options.sh` — `ONLY_PHP_x_y` + `PHP_x_y` defaults and their `--only-php-x-y` / `--no-php-x-y` case entries.
- `lib/set_variables.sh` — `ALL_PHP_VERSIONS`, `ALL_ONLY_PHP_FLAGS`, `ALL_PHP_FLAGS`, and `DEPRECATED_PHP_VERSIONS`.
- `sphp.sh` — `brew_array` and `php_array`.
- `lib/print_help.sh` and `README.md` option tables.
- Preset blocks in `init_options.sh` (e.g. `--p-common` pins a specific `ONLY_PHP_x_y=true`).

`do_php.sh` installs Homebrew-deprecated PHP versions (listed in `DEPRECATED_PHP_VERSIONS`) from the `shivammathur/php` tap instead of core, tapping it once on demand.

### Config templates

`httpd-vhosts.conf` and `php.ini` are templates shipped with the repo. `do_apache.sh` reads `httpd-vhosts.conf`, substitutes `{APACHE_DOC_ROOT}` and `{APACHE_SERVER_NAME}` placeholders, backs up the existing vhosts file once (`.bak`), and writes the result. The single `php.ini` is installed to `/usr/local/php/php.ini` and symlinked into every PHP version's `conf.d`. Apache `httpd.conf` is edited in place via `sed -i.bak` / `perl -i.bak` line rewrites — these regexes are fragile against Homebrew's default config layout.

### sphp.sh

Standalone PHP switcher (adapted from Phil Cook / Andy Miller). Unlinks all `php@*` formulae, links the requested one, and rewrites the `LoadModule php*_module` line in Apache's `httpd.conf` (module name/path differs across PHP 5/7/8). It is both installed by `do_php.sh`/`self-install` and committed as a runnable script.

### Self-update

`--self-update` clones `$SCRIPT_REPO` (default the GitHub repo, overridable via `--script-repo=`) into `/tmp` and runs that copy's `self-install`. `self-install` rsyncs the repo into `/usr/local/macos-web-development/` and symlinks `macos-web-development.sh` → `/usr/local/bin/macos-web-development`.

## Conventions

- Colors come from `init_colors.sh` semantic vars (`C_1`, `C_2`, `C_INFO`, `C_EM`, `C_0` to reset) — use these in `echo -e`, not raw ANSI codes.
- `set -e` is active; a failing command aborts the whole run.
- Idempotency: install steps check whether something already exists (`brew ls --versions`, `[ -f ... ]`) and skip rather than overwrite, printing an "already installed / will not overwrite" message in `C_2`.
